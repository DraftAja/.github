## Kenapa serah terima ini ada

Panel perapihan dan asisten chat di web memakai empat tipe tulisan tangan: `Generation`, `GenerationStatus`, `CleanupReservation`, dan `ChatReply`. `GenerationStatus` bahkan memuat nilai `processing` yang tidak pernah dikirim API. Serah terima ini memindahkan keempatnya ke `openapi.json`.

## Isi paket

| Bagian di `openapi.json` | Isi | Menggantikan |
|---|---|---|
| Respons `GET /ai/generations/{id}` | `generation_id`, `status` (enum `pending`, `succeeded`, `failed`), `operation`, `progress_done`, `progress_total`, `accepted_at`, `output`; untuk perapihan juga `source_revision`, `expires_at`, `expired`, `can_accept` | `Generation`, `GenerationStatus` |
| Respons `POST /laporan/{id}/tidy` (202 dan 200) | `generation_id`, `status`, `source_revision`, `progress_done`, `progress_total`, `reused` | `CleanupReservation` |
| Respons `POST /ai/chat` | `reply`, `generation_id` | `ChatReply` |
| Respons `POST /ai/generate` | `result`, `generation_id` | tidak dipakai web, tetap dikontrakkan |
| Status error setiap endpoint AI | sesuai persetujuan [H3](H3.md) | |

Field yang hanya ada untuk perapihan ditandai opsional di skema, karena operasi lain tidak mengirimnya.

## Syarat sebelum dikirim

- [ ] `composer api:spec` dijalankan dan `openapi.json` ikut di-commit
- [ ] Tes yang ada di `tests/Feature/Ai` dan `tests/Feature/Documents` tetap lulus, karena bentuk JSON tidak boleh berubah
- [ ] Bila H6 belum merge, PR ini tetap memakai skema `ErrorResponse` dari CORE-2 setelah keduanya merge (koordinasi dengan Octaf)

## Cara mengirim
