## Kenapa serah terima ini ada

Job E2E di CI web menjalankan API `develop` sungguhan, tetapi tanpa kunci Groq atau Gemini. Akibatnya alur perapihan, analisis pola, dan chat tidak pernah diuji dari antarmuka. Memakai kunci sungguhan di CI juga tidak diinginkan: berbayar, lambat, hasilnya tidak tetap, dan kunci harus disimpan sebagai secret. Provider palsu memberi jawaban tetap sehingga E2E bisa memeriksa seluruh alur sampai usulan diterima.

## Isi paket

| Artefak | Isi |
|---|---|
| Cara menyalakan | Satu variabel env di API, nama disepakati di issue, misalnya `AI_FAKE=true`. Hanya diterima saat `APP_ENV` bernilai `local` atau `testing`; `env:verify` menolaknya di staging dan produksi. |
| Perilaku analisis pola | Mengembalikan pola tetap yang lolos validator, sehingga template berstatus `ready` dalam beberapa detik |
| Perilaku perapihan | Mengembalikan setiap blok dengan `id` sama dan teks yang diberi perubahan kecil yang bisa dikenali tes, misalnya huruf awal kalimat dijadikan kapital, tanpa menambah fakta |
| Perilaku chat | Jawaban tetap berbahasa Indonesia |
| Pemicu kegagalan | Cara memicu `provider_failed` dan `provider_unavailable` dari provider palsu, untuk kasus negatif QA |
| Dokumentasi | Bagian baru di doc 09 API, dirujuk dari web doc 07 |
| Perubahan CI web | Di langkah "Siapkan API" job E2E: variabel env provider palsu, dan `php artisan queue:work` di latar belakang. Langkah itu saat ini hanya menjalankan `php artisan serve`, sehingga analisis dan perapihan tidak akan diproses. |
