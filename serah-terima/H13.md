## Kenapa serah terima ini ada

Pengguna sekarang baru tahu kuota AI habis setelah permintaannya ditolak, dan tidak tahu kapan kuota pulih. Satu perapihan dokumen panjang bisa memakai beberapa unit sekaligus, karena dokumen dipotong per 20 blok atau 3.000 karakter. Selain itu, usulan perapihan dikirim sebagai string JSON di dalam JSON, sehingga web harus mem-parse ulang dan menebak bentuknya.

## Isi paket

| Perubahan | Bentuk |
|---|---|
| `GET /api/v1/ai/quota` | `{limit, used, remaining, resets_at}`. `used` adalah jumlah `quota_units` hari ini sejak 00.00 waktu aplikasi (UTC). `resets_at` ISO 8601, sama dengan pukul 07.00 WIB. `limit: 0` berarti tanpa batas. |
| Field `proposal` di `GET /api/v1/ai/generations/{id}` untuk perapihan | Objek `{blocks: [{id, text}]}`, null sampai `succeeded` atau bila usulan kedaluwarsa |
| `output` untuk perapihan | Tetap dikirim, ditandai deprecated di `openapi.json`. Dihapus paling cepat satu sprint setelah web memakai `proposal`. |

## Syarat sebelum dikirim

- [ ] Proposal kontrak berlabel `kontrak-disetujui`
- [ ] Tes: setelah satu perapihan 3 potongan, `used` bertambah 3; permintaan ulang dengan `request_key` sama tidak menambah `used`
- [ ] Tes: `proposal` berisi blok dengan `id` sama dengan `output` lama
- [ ] `composer api:spec` dijalankan
- [ ] Rencana penggantian field di doc 18 diperbarui dengan tanggal deprecated
