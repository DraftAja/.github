## Kenapa serah terima ini ada

Fase 1 baru lengkap ketika perubahan API (CORE-3, AI-3) dan antarmuka (WEB-3) sama-sama ada di `develop`. Serah terima ini datang dari FE karena PR web adalah yang terakhir merge, sesuai aturan urutan merge di doc 17: PR API lebih dulu, PR web merujuknya.

## Isi paket

| Area | Yang diuji QA |
|---|---|
| Status dokumen | Draf ke final lewat "Tandai final"; dokumen final terbuka dalam mode baca; "Buat revisi" membuka draf baru yang menyimpan rujukan ke dokumen asal |
| Konflik | Dua tab menyunting bagian yang sama; tab kedua menampilkan dialog konflik dan isi terbaru tidak hilang |
| Kuota | Kartu kuota sesuai `GET /ai/quota`; tombol AI nonaktif setelah kuota habis sampai waktu pulih |
| Persona | Asisten chat tidak menyebut LaporBot atau mahasiswa; form tidak memuat istilah akademik; kolom identitas baru tampil di "Data dokumen" |
| Kategori | Dokumen baru punya kategori dari 8 kunci |
| Ekspor | Surat dan Notula tanpa sampul dan daftar isi; proposal dengan sampul |
| Halaman dasar | `/kebijakan-privasi`, halaman tidak ditemukan, halaman galat |
| Penanda | `[perlu dilengkapi]` disorot dan dihitung |

## Cara penerima mereview

- [ ] Pasangan commit bisa dijalankan dari `develop` kedua repo tanpa langkah tambahan selain migration dan seeder

Pengirim memperbaiki lalu melapor ulang di issue yang sama; selama itu penerima tetap memakai versi terakhir yang disetujui ([aturan](README.md#bila-reviewer-tidak-setuju)).
