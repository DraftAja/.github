## Kenapa serah terima ini ada

Ada dua jenis PostgreSQL yang dibutuhkan CORE-5, dan hanya satu yang bisa disiapkan BE sendiri:

| Lingkungan | Sudah ada? | Dipakai untuk |
|---|---|---|
| `postgres:16-alpine` di Docker Compose lokal dan di job CI "Tes (PostgreSQL 16)" | Sudah ada. Database `draftaja_test_*` dibuat `docker/postgres/init.sql`. | Rangkaian tes PHPUnit, termasuk dua tes konkurensi |
| Salinan sekali pakai yang menyerupai Azure Database for PostgreSQL Flexible Server: TLS wajib, versi dan pengaturan server sama, berisi salinan data `draftaja_shared_dev` | Belum ada | Uji upgrade dari skema yang sudah berisi data, `documents:schema-check`, uji pemulihan dari backup |

Serah terima ini tentang lingkungan kedua. Database Azure bersama yang dipakai tim tidak boleh dipakai untuk uji ini (aturan di `CLAUDE.md`: tidak boleh `migrate:fresh`, dan tes tidak boleh diarahkan ke Azure).

Per 4 November 2026, job CI PostgreSQL berstatus hijau hanya karena langkah PHPUnit ditandai `continue-on-error`. Isinya 208 tes dengan 154 error dan 2 failure, karena migration `2026_10_28_000002_add_document_workflow_state` menolak skema PostgreSQL yang dibuat dari nol. Masalah ini diperbaiki di CORE-5 dan bisa diperbaiki tanpa menunggu H15. H15 dibutuhkan untuk membuktikan bahwa perbaikan itu juga aman terhadap database yang sudah berisi data.

## Isi paket

| Item | Lewat |
|---|---|
| Host, port, nama database (`draftaja_test_*` atau nama lain yang disepakati dan bukan `draftaja_shared_dev`, `draftaja_staging`, `draftaja_prod`), username, password | Kanal aman |
| Mode TLS (`DB_SSLMODE=require`) dan sertifikat CA bila memakai `verify-full` | Kanal aman |
| Aturan firewall yang mengizinkan IP mesin Octaf atau runner | Dicatat di issue tanpa IP |
| Backup `draftaja_shared_dev` yang sudah dipulihkan ke instance ini | Dicatat di issue: tanggal backup dan versi migration terakhir |
| Izin tertulis: boleh `migrate`, boleh dihapus setelah uji, batas waktu pemakaian | Komentar PM di issue CORE-5 |

## Syarat sebelum dikirim

- [ ] Instance terpisah dari database bersama, staging, dan produksi
- [ ] Backup yang dipulihkan sudah terbukti bisa dibuka
- [ ] Biaya instance disetujui PM dan dijadwalkan dihapus setelah uji

## Cara mengirim

1. Kirim kredensial lewat kanal aman.
2. Tulis di issue CORE-5: "Akses PostgreSQL uji diserahkan", tanggal, batas waktu, dan versi migration data salinan. Tanpa rahasia.

## Cara penerima memeriksa

- [ ] Koneksi berhasil dengan `DB_SSLMODE=require`
- [ ] `php artisan documents:schema-check` berjalan baca-saja dan mencetak hasil
- [ ] Nama database lolos `TestDatabaseGuard` bila dipakai untuk PHPUnit, atau PHPUnit tidak diarahkan ke instance ini bila namanya bukan `draftaja_test_*`

## Dipakai untuk

Uji upgrade dari data nyata, schema check, dan uji pemulihan di CORE-5. Hasilnya dikirim ke PM lewat [H21](H21.md).

## Bila terlambat

Octaf memperbaiki migration dan menjalankan rangkaian tes di Docker Compose lokal sampai hijau, lalu menghapus `continue-on-error` dari job CI. Uji upgrade dan pemulihan ditunda, dan risikonya dicatat di doc 10 agar bisa diterima tertulis oleh PM saat PM-4.
