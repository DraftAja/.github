## Kenapa serah terima ini ada

Alvira butuh tipe respons usaha, uang, dan stok dari `openapi.json`, bukan tipe tulisan tangan.

## Isi paket

| Perubahan | Bentuk |
|---|---|
| `/businesses`, `/businesses/{id}`, `/switch` | Daftar usaha dengan batas dan status `baca_saja` |
| `/cash-transactions`, `/cash-categories` | Rupiah sebagai integer |
| `/products`, `/movements`, `/productions` | Jumlah sebagai string desimal tiga angka |
| `/me`, `/me/preferences`, `/me/onboarding/complete`, `/getting-started` | Field `areas`, `onboarded_at`, `preferred_categories`, `dismissed_hints`; Langkah mulai dengan `key` dan `done` (BE-31) |
| Kode error | `business_limit_reached`, `business_read_only`, `stock_negative` |

## Syarat sebelum dikirim

- [ ] Proposal kontrak berlabel `kontrak-disetujui`
- [ ] Tes BE-19 sampai BE-21 hijau di SQLite dan PostgreSQL
- [ ] `composer api:spec` dijalankan

## Cara mengirim

1. Merge PR API.
2. Pasang label `butuh-fe` di issue WEB-6 dan tautkan PR API.

Setelah itu buka issue **Laporan selesai** berisi tautan PR atau bukti di atas, lalu mention @alvirarisky (Alvira) sebagai reviewer. Pengirim langsung lanjut ke pekerjaan berikutnya tanpa menunggu tanggapan.

## Cara penerima mereview

- [ ] `npm run api:sync && npm run api:types` tanpa error
- [ ] Tipe usaha, uang, dan stok ada di `schema.d.ts`

Tanggapi di issue laporan. Setuju: pasang label `disetujui`. Tidak setuju: pasang label `perlu-perbaikan` dan tulis yang kurang. Pengirim memperbaiki lalu melapor ulang di issue yang sama; selama itu penerima tetap memakai versi terakhir yang disetujui ([aturan](README.md#bila-reviewer-tidak-setuju)).
