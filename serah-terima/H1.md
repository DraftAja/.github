## Kenapa serah terima ini ada

CORE-2 mengubah bentuk semua respons error API (BE-03). Perubahan itu memengaruhi setiap layar di web. Sebelum kode itu ditulis, harus sudah ada aturan yang memaksa Alvira meninjau setiap PR yang menyentuh `openapi.json`. Tanpa CODEOWNERS dan branch protection, PR kontrak bisa merge hanya dengan persetujuan sesama BE.

## Isi paket

| Artefak | Di mana | Isi minimal |
|---|---|---|
| `TEAM_CONTRACT.md` v1.1 | Backend-Laravel, `develop` | Kepemilikan per repo, aturan PR lintas repo, Definition of Done tambahan, nomor versi dan tanggal di kepala dokumen |
| `.github/CODEOWNERS` | Backend-Laravel | `docs/api/openapi.json` dimiliki `be-core`, `be-ai`, dan `fe`; folder AI dimiliki `be-ai`; folder inti dimiliki `be-core` |
| `.github/CODEOWNERS` | Frontend-Nextjs | Semua berkas dimiliki `fe`; `contracts/` dan `src/lib/api/` juga dimiliki `be-core` dan `be-ai` |
| Branch protection | `main` dan `develop` kedua repo | PR wajib, 1 approval untuk `develop`, 2 untuk `main`, review pemilik kode wajib, status check CI wajib, tanpa force push |
| Label | ketiga repo | `be-core`, `be-ai`, `fe`, `qa`, `docs`, `bug`, `feature`, `blocked`, `priority-high`, `kontrak`, `kontrak-disetujui`, `memecah-kontrak`, `butuh-api`, `butuh-fe`, `siap-rilis` |

## Syarat sebelum dikirim

- [ ] PR kontrak v1.1 disetujui minimal 4 dari 5 anggota (kontrak bagian 14)
- [ ] CODEOWNERS memakai username GitHub asli, bukan placeholder `@[be1-username]`
- [ ] Alvira dan Louis sudah menjadi anggota organisasi, karena CODEOWNERS hanya berlaku untuk akun yang punya akses tulis

## Cara mengirim

1. Merge PR kontrak v1.1 dan PR CODEOWNERS di kedua repo.
2. Aktifkan branch protection sesuai tabel di atas.
3. Buka satu PR uji kecil (misalnya mengubah satu kalimat di `openapi.json` tanpa merge) untuk memastikan GitHub otomatis meminta review Alvira, lalu tutup PR itu.
4. Umumkan di grup dengan tautan ke PR yang sudah merge.

## Cara penerima memeriksa

- [ ] Octaf membuka PR draf ke `develop` dan melihat reviewer wajib muncul otomatis
- [ ] Push langsung ke `develop` ditolak GitHub
- [ ] Label `kontrak` tersedia untuk issue proposal BE-03

## Dipakai untuk

Proposal kontrak BE-03 dan PR-nya di CORE-2 berjalan dengan reviewer wajib.

## Bila terlambat

Octaf tetap boleh menulis proposal kontrak BE-03 dan mengerjakan CORE-1. PR BE-03 tidak di-merge sebelum H1 diterima. Bila terlambat lebih dari 3 hari kerja, Octaf meminta Alvira me-review manual dan PM mencatat pengecualian itu di PR.
