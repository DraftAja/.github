## Kenapa serah terima ini ada

Katalog template di web harus dibangun dari data API, bukan dari daftar statis di frontend, supaya label, warna, dan urutan kategori punya satu sumber. Form buat dokumen juga harus dibangun dari kolom isian template (`template_fields`), bukan kolom sampul akademik.

## Isi paket

| Perubahan | Bentuk minimal |
|---|---|
| `GET /api/v1/categories` | Daftar 8 kategori: `key`, `label`, `color`, `ink` (warna teks di atasnya), urutan |
| `GET /api/v1/templates` dengan saringan | Query `category` (salah satu dari 8 kunci) dan `q` (nama atau kode) |
| `GET /api/v1/templates/{id}` | Detail: `code` (misalnya `SRT-01`), `name`, `category`, kalimat "Kapan dipakai", daftar bagian, kolom isian, tata letak ekspor (sampul, daftar isi) |
| Kolom isian di detail template | Per kolom: `key`, `label`, `type` (`teks`, `teks_panjang`, `tanggal`, `waktu`, `angka`, `rupiah`, `orang`, `daftar`), `required`, `source` (`input`, `profil_instansi`, `sistem`), urutan |
| `field_values` di `LaporanResource` dan di body `POST`/`PUT /laporan` | Objek `{key: nilai}` |
| Peringatan kolom wajib kosong | Daftar `key` kolom wajib yang belum diisi, misalnya `missing_required_fields` di detail dokumen |
| `report_types` di `GET /laporan/options` | Ditandai deprecated di `openapi.json` |

## Syarat sebelum dikirim

- [ ] Proposal kontrak berlabel `kontrak-disetujui`
- [ ] 64 template ter-seed dengan kolom isian (lihat [H18](H18.md))
- [ ] `composer api:spec` dijalankan, kategori dan tipe kolom berupa enum di `openapi.json`
- [ ] Tes: saringan kategori hanya mengembalikan template kategori itu; nilai kategori di luar 8 kunci ditolak 422

## Cara mengirim

1. Merge PR API.
2. Pasang label `butuh-fe` di issue WEB-4 dan tautkan PR API.

## Cara penerima memeriksa

- [ ] Tipe kategori, detail template, dan kolom isian ada di `schema.d.ts`
- [ ] `GET /categories` mengembalikan warna yang sama dengan `src/features/landing/content.ts`
